AQ-DVC-001 — Demonstration version control

A demonstration is usable as evidence only if a reader years later can establish exactly what ran, on what build, measured by what instruments, under what claim, and witnessed by whom. This document defines the mandatory record for every Akasha-Q run — evidential or not — and the identifier scheme that binds a run to its artefacts. It defines a record format to which future runs will be held; no run has yet been performed and no element has reached laboratory validation. The format applies from DM-0 onward and to every architecture tier (CA, Y1, FR, LH).

THE NINE MANDATORY FIELDS

Correct-abstention. Where the element returned abstain, safe-hold or deny and that was the right outcome under the trust state in force, F-9 records correct-abstention. Under DC-3 abstention is a permitted output; it is recorded as a pass against a claim about refusal, or as an expectation failure of the script (class FC-C), and never as an element fault.

MINIMUM RECORD RULE (DC-2)

If any of F-1 to F-9 cannot be completed, the missing field is written as Undetermined with the reason, and the run's disposition defaults to NON-EVIDENTIAL. A missing field never defaults to benign and is never inferred from a neighbouring run. Completeness is a precondition of evidence, not a formatting preference.

AQ-DEMO-ID ALLOCATION

Figure 1 — Identifier anatomy

  AQ-DEMO-L2-NODE1-20260830-007-a02
  |       |  |     |        |   |
  |       |  |     |        |   +-- attempt index within this allocation (a01..)
  |       |  |     |        +------ allocation sequence within the date (001..)
  |       |  |     +--------------- allocation date, UTC, YYYYMMDD
  |       |  +--------------------- element under demonstration (AQ-NODE-1)
  |       +------------------------ layer in scope (L0..L9)
  +-------------------------------- fixed prefix
  • An ID is allocated before the run is armed. An ID may never be created after data exists.
  • IDs are monotonic within (layer, element, date). They are never reused and never deleted.
  • A change to the claim text (F-3) or to configuration identity (F-4) closes the allocation and requires a new sequence number. Only a repeated attempt under an identical claim and identical configuration increments the attempt index.
  • An allocation that is not run closes as NOT RUN with a reason. Under DC-2 an unexplained gap in the sequence is itself a finding, investigated as such.
  • The ID appears inside the artefacts, not merely beside them: burned into recorded video frames, embedded in raw capture filenames, printed on every slide, figure and report line that cites the run.
  • The register is append-only. A correction is a new entry referencing the original; an entry is never edited in place.

NON-EVIDENTIAL RUN MARKING

NON-EVIDENTIAL RUN

A run whose purpose is communication rather than measurement is marked NON-EVIDENTIAL at allocation. It may use replayed capture, simulated inputs, scripted timing or a partial article, provided each such element is declared on the material itself. It carries a visible NON-EVIDENTIAL RUN marker on the artefact — on the video frame, on the slide, in the figure caption — not only in metadata, because metadata does not travel with a screenshot. It may not be cited in any evidence-level determination on the Part 12 ladder, in any funding, partnership or recruitment document as a technical result, or in any external statement about capability. Every number shown in such a run is tagged MODELLED unless F-5 was completed.

REHEARSAL VERSUS VALIDATION — AQ-RL-26.14

RULE AQ-RL-26.14

A rehearsal exercises the presentation of an element. A validation tests a claim about the element. The two shall never be the same run. A rehearsal can never raise an evidence level; a rehearsal that contradicts a standing claim still lowers one.

DimensionRehearsalValidation
1 PurposeExercise delivery, timing, narration and recovery of a presentationTest one falsifiable claim about the element
2 Claim binding (F-3)None. The field names the claim being illustrated and is marked ILLUSTRATIVEOne claim, fixed before allocation and hash-bound to the ID

6 Failure handlingAQ-DEMO-FAIL-001 steps 1 to 3 apply in full; steps 4 to 7 apply where the observation contradicts a standing claimAQ-DEMO-FAIL-001 applies in full, every step, every time
7 Effect on the ladderCan lower a rung. Can never raise oneCan raise a rung on a pass with a complete record; lowers a rung on a fail

Row 7 is the asymmetry that makes the rule enforceable rather than decorative, and it follows directly from DC-4: degradation is monotonic without validation. Evidence is gained only under evidential conditions with a complete F-1 to F-9 record; it can be lost anywhere, including in a rehearsal, an internal walkthrough or a conversation held over a bench. Nothing reaches the Part 12 evidence ladder except through a sealed evidential run record, and every rung asserted anywhere in the charter carries the AQ-DEMO-ID that supports it.
