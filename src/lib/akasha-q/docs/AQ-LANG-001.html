AQ-LANG-001 — Language discipline standard

PURPOSE AND SCOPE

This standard governs the wording of every artefact that leaves the programme record: charter parts, design notes, review packs, demonstration scripts and captions, interface strings, run reports, correspondence and any briefing derived from them. It restricts what may be claimed. It places no restriction on what may be built or attempted; ambition belongs in the capability statement, discipline belongs in the evidence statement, and the two are written in the same sentence.

Architecture tier CA. Evidence level of this document: Theory — it is a defined process, not a validated one. It applies from DM-0 onward and is binding on all ten layers L0–L9.

NEVER ASSERTED

Unhackable. Impossible to intercept. Universally quantum-secure. Information-theoretically secure at system level. Satellite-ready. Space-proven. Operational. These are not degraded into hedged forms; they are removed. No qualifier rescues them, because each names a property the programme has no measurement path to at its current rung.

RESERVED DESCRIPTORS

secure, resilient, autonomous, high-precision, low-latency, quantum-secure, robust, real-time, scalable, reliable, intelligent, proven, validated. None may stand as a bare adjective. Each may appear only in a sentence that also names the measured quantity (or its explicit absence), the conditions under which it applies, and the evidence level.

TENSE RULE

Nothing has been built and no element has reached Lab validation. Past tense is therefore permitted only for process events — a review was held, a document was issued, a rule table was fixed. Past tense about system performance is prohibited outright, including in figure captions, commit messages and internal drafts, because internal drafts are the source text for external artefacts and the tense survives the copy.

THE GENERAL PATTERN

Every acceptable form above satisfies the same four-slot structure. A statement missing any slot is not a weaker claim — it is an unreviewable one, because a reader cannot tell what would falsify it.

Figure 1 - Anatomy of an acceptable capability statement

  +--------------------------------------------------------------+
  |  slot 1  CONDITIONS                                          |
  |          configuration, environment, assumption set,          |
  |          adversary or failure model where relevant            |
  +--------------------------------------------------------------+
  |  slot 2  RUN IDENTITY                                        |
  |          which run(s), on which article, at which DM level;   |
  |          'no run has been performed' is a valid filling       |
  +--------------------------------------------------------------+
  |  slot 3  QUANTITY                                            |
  |          the named metric with its value and DC-1 tag         |
  |          (MEASURED / DERIVED / MODELLED)                      |
  |          OR the explicit absence: 'the metric is undefined'   |
  +--------------------------------------------------------------+
  |  slot 4  NOT ESTABLISHED                                     |
  |          what the statement does not support, named           |
  |          positively, in the same sentence or the next         |
  +--------------------------------------------------------------+

  slot 3 absent  -> the sentence is marketing, not a claim
  slot 4 absent  -> the reader will supply the strongest reading
  slot 2 absent  -> the claim cannot be re-run and cannot be retired

Two consequences follow directly. First, a capability may be described as ambitiously as the design warrants, provided slot 4 is filled: "the terminal is designed to operate across all six rungs; nothing above rung 1 exists" is compliant, while "a six-rung terminal" is not. Second, an absence is written as a value, mirroring DC-2 at the level of prose: "the metric is undefined and will be established from bench measurement" is an acceptable slot-3 filling; silence is not.

REVIEW PROCEDURE

  • Pass 1 — reserved-word sweep. Locate every reserved descriptor and every past-tense verb attached to system behaviour. Each occurrence is either rewritten to the four-slot form or deleted.
  • Pass 2 — slot audit. For each remaining capability sentence, mark which of the four slots it fills. Any sentence below four is returned to its author with the missing slot named, not silently edited.
  • Pass 3 — evidence-level check. Every capability statement carries an evidence-level chip drawn from the Part 12 ladder, and no chip may exceed the level of the run record it cites. A statement citing no run cannot exceed Concept or Theory.
  • Derived artefacts inherit. A slide, caption or summary derived from a compliant document must carry the same evidence level and the same slot-4 statement. Compression is not an exemption; if the four slots do not fit, the claim is cut, not the qualification.

WHAT THIS STANDARD DOES NOT DO

It does not decide whether a claim is true, and it does not substitute for review by the layer that owns the subject. A sentence can satisfy all four slots and still be wrong about the physics. It also carries no geopolitical, sovereign-capability or defence framing of any kind, and artefacts introducing such framing are out of scope of the programme record entirely rather than being rewritten into compliance. Conflict CF-4 — the tension between describing intended capability and the reader's tendency to read intent as achievement — is managed by slot 4 and is not considered closed.
