## Engineering ledger

### E-01 — `= ANY(${jsArray})` live in five places in the mail platform (P0/P1)

**Found by** `src/lib/pg-array.test.ts`, which scans the source for the pattern and had been red.

**Root cause.** Drizzle renders `sql\`x = ANY(${jsArray})\`` as `x = ANY(($1, $2, $3))` — a *record*
literal, not an array. Postgres answers *"op ANY/ALL (array) requires array on right side"* and the
statement never runs. Proved by rendering each shape through `PgDialect.sqlToQuery` with no database
involved:

```
= ANY(array)   ->  "WHERE id = ANY(($1, $2, $3))"   params ["a","b","c"]
IN textIn      ->  "WHERE t IN (SELECT jsonb_array_elements_text($1::jsonb))"   params ["[\"a\",\"b\",\"c\"]"]
```

Every one of the five sat behind a `catch`, which is why none of them surfaced.

| Site | What was broken |
| --- | --- |
| `src/lib/mailplatform/suppression.ts:97` | `checkSuppressedResult` is the fail-closed suppression gate. The query threw for **every** send with at least one recipient, so the gate returned `{ok:false}` and outbound mail was refused platform-wide. |
| `src/lib/mailplatform/adapters/event-bus-postgres.ts:132` | Event query filtered by `eventTypes` threw; caught, returned an empty page. The events list showed nothing whenever a type filter was applied. |
| `src/lib/mailplatform/adapters/event-bus-postgres.ts:206` | Every analytics metric except `events` carries a type list, so `messages_sent`, `delivered`, `bounced`, `opened`, `clicked`, `contacts_created` all failed. |
| `src/lib/mailplatform/adapters/message-store-postgres.ts:404` | `getThread` loads recipients for the whole thread in one query; it threw and the catch returns `[]`, so opening any thread rendered empty. |
| `src/lib/mailgov/schema.ts:472` | `tablesExisting` swallowed the error and returned an empty set, so governance health reported every table as missing. |

**Fix.** All five now use the repository's own canonical helpers `textIn()` / `uuidIn()` from
`src/lib/pg-array.ts` with the `IN ${...}` form — one bound parameter, no escaping, index-usable.
`mail_recipients.message_id` is `UUID`, so that site uses `uuidIn`; the rest are text and use
`textIn`. `c.relname` is cast to `text` explicitly rather than relying on a `name = text` operator.

**Verification.** `src/lib/pg-array.test.ts` 16/16 (was 15/16). Its scanner now reports no live
instance in `src/`; the only remaining matches in the tree are the comments that document the bug.

### E-02 — the deployment checklist had rotted by 17 variables (P1)

**Found by** `src/lib/deployment-readiness.test.ts`, which compares `REQUIREMENTS` against every
`process.env.X` / `import.meta.env.X` the source actually reads.

**Root cause.** The mail engine seam, the integration layer, the metrics endpoint and the host's own
injected values had all landed since the list was last reconciled. A checklist that omits a variable
is worse than none, because somebody trusts it and stops looking.

Two of the seventeen **fail closed**, which is what makes this more than bookkeeping:

- `WEBHOOK_SIGNING_KEY` — `src/lib/mailplatform/webhooks.ts` refuses to send rather than send
  unsigned. Unset means **no outbound webhook is delivered at all**, and the deployment screen said
  it was ready.
- `MAIL_APP_SHARED_SECRET` — `/api/mail/engine/events` and `/api/mail/engine/suppressions` refuse
  **every** request when it is unset, so deliveries, bounces and complaints never reach the platform.

The rest are recorded with an honest severity and a sentence saying what actually stops: the
`MAIL_SERVICE_*` pair, `MAIL_WEBHOOK_SECRET`, `MAIL_TRANSPORT`, `MAIL_INBOUND`, `IMAP_HOST`,
`MAIL_MAX_INBOUND_BYTES`, `MAIL_ALLOW_PRIVATE_SMTP`, `MAIL_GEOLOCATE_OPENS`, `MAILINT_ENVIRONMENT`,
`METRICS_TOKEN`, `SITE_URL`, and the three host-injected `VERCEL_*` values — the last group listed
because this checklist is also read when moving *off* the current host, where all three vanish and
each changes a behaviour quietly rather than failing.

**Verification.** `src/lib/deployment-readiness.test.ts` 228/228 (was 197/198).

### E-03 — no session ownership on the AI interview endpoints (P1, security)

**Found by** an authorization sweep of all 393 API routes: which of them perform no authentication
or authorisation of their own, given that `src/middleware.ts` hard-exempts `/api/`.

Five endpoints under `/api/aquintutor/interview/` took a `sessionId` out of the request body and did
the work. That string was the entire credential. Each file carried a note describing the hole and
deferring the fix on the grounds that binding to a signed-in user would change *who may call the
route*.

| Endpoint | What possession of a session id bought |
| --- | --- |
| `enroll-face` | Overwrite the **biometric reference descriptor** of an in-progress interview and set `preflight_passed = true` — substitute your own face as the candidate's reference, which every later identity check is measured against. |
| `id-doc` | Replace the **government ID photograph** a reviewer will look at, on any session id; and an unauthenticated 12 MB upload into the public blob store. |
| `log-event` | Drive another person's `risk_score`, `strikes_count` and `tab_switches`, and trip auto-termination in their name — into a pipeline `CLAUDE.md` says a human reads as evidence. |
| `turn` | Append transcript turns to a named candidate's record, and spend LLM tokens doing it. |
| `end` | End someone else's interview and push a "completed" notification naming them to admins. |

**Fix.** `src/lib/aquin/interview-session.ts`. `/start` mints an HMAC-SHA256 signature over the new
session id and sets it as an **HttpOnly, SameSite=Lax** cookie; the five writers require it back and
check *both* halves — the cookie must name the same session the request acts on, and the signature
must be the one this deployment would mint. Naming a different session is refused even when the
signature is genuine, so one legitimately held cookie is not a key to every other interview.

This is the second option the original notes named ("a one-time token issued when it starts"), and it
is a mechanism change, not a policy one: the session is bound to **the browser that started it**, not
to an account. Anonymous candidates still take interviews with no sign-in. No client change was
needed — every caller already uses `credentials: 'same-origin'`.

Fails closed with no `SESSION_SECRET`: nothing can be signed, so nothing verifies and every guarded
write is refused. That is not a new outage — `SESSION_SECRET` is already a *blocking* requirement.

**The one cost, stated plainly.** A session already in progress when this ships has no cookie, so its
next write is refused and that candidate has to start again. A grace period is impossible without a
column recording "this session was never bound", and an absent cookie treated as permission is the
hole itself. **Deploy it when no interview is being sat.**

**Verification.** `src/lib/aquin/interview-session.test.ts`, 29 assertions, including the two that
matter: a genuine cookie pointed at another session is refused, and an unconfigured deployment
verifies nothing rather than everything.

### E-04 — hand-escaped JSON in `sql.raw` (P3)

`enroll-face.ts` built four statements as `sql.raw("'" + JSON.stringify(x).replace(/'/g, "''") + "'::jsonb")`.
Not injectable — doubling `'` is the correct escape inside a literal, and `fingerprint` is arbitrary
browser-supplied JSON that this handled correctly — but it is one editing mistake away from being so.
Now bound parameters cast to `jsonb`, which needs no escaping to be right.

### E-05 — raw NUL bytes in two source files (P4)

`src/lib/mailapi/tracking.ts` and `src/lib/mind/encoder.ts` contained literal NUL bytes inside string
literals, used as separators in HMAC signing and hash keys. Intentional in meaning, hazardous in
form: git, grep and diff all classified the files as binary, and a text-mode filter that dropped the
byte would silently change **every tracking signature the platform has issued** with no error
anywhere. Replaced with the `\0` escape — byte-identical runtime strings, and no source file under
`src/` or `public/` now contains a NUL.

### E-06 — a backtick inside a `sql` template broke the build (P0)

**Found by** running `npx astro build` and reading its real exit code.

`src/pages/portal/employee/onboarding.astro:154` carried a SQL comment written as
``-- `emp` is resolved once when the page renders`` — inside a `sql\`` template literal that opens at
line 126 and closes at line 159. A backtick inside a template literal *closes it*, so esbuild
reported `Expected ")" but found "emp"` and the whole build failed.

The file was edited at 20:38 during this session, after the first (passing) build at 20:32 — a
concurrent edit in this tree, not a change made by this audit. Fixed by dropping the two backticks;
the sentence is unchanged.

**Also worth recording as a method note:** the first attempt to verify this piped the build into
`tail`, so `$?` reported the exit code of `tail` and printed `BUILD_EXIT=0` over a failing build. A
green number from a pipeline proves the last command in the pipe ran. Re-run without the pipe.

**Verification.** `npx astro build` → exit 0, "Complete!". A scan added for the general case reports
no other backtick inside an open `sql` template anywhere in `src/`.

### E-07 — a test that failed for being busy (P3)

`mail-engine/test/log-once.test.ts` passed on its own (18 files / 225 tests green in isolation) and
timed out at the 5-second default inside the full suite, immediately after a 161-second build had
rewritten `dist/`. Its throttling logic runs on an injected clock and costs nothing; the wall-clock
is 151 real spool writes into a temp directory, so the default timeout was an assertion about disk
speed rather than about the code.

Given an explicit 30-second budget. No assertion changed. A gate that goes red for being busy is a
gate people learn to re-run instead of read — which is the same failure mode as a checklist nobody
trusts (E-02).

## E-08 — the unauthenticated answer key (P0)

`src/pages/api/aquintutor/practice/answer.ts` looked a question up by id alone and returned
`correct_answer`, the resolved model answer and the explanation. `test_questions` is not a practice
bank — it is *the* question table, written by `/admin/tests/[id]` and marked from by
`/api/tests/submit`. The route has no authentication of any kind (`user` is read only to award XP).
Its sibling `practice/start.ts` has always required the parent test to be `is_published` **and**
practice-enabled and strips `correct_answer` before replying; the door that gives *feedback* never
asked. A candidate inside a live proctored test — whose question UUIDs are in their own DOM via
`define:vars` — could read the mark scheme one question at a time, signed out, from any machine.

Fixed by applying the sibling's own gate: join `tests`, require `is_published`, `practice_enabled`
and `q.is_active`. Same 404 for "no such question" and "not practisable", so the endpoint cannot be
used to map which ids belong to a live assessment. Confirmed P0 by three independent verifiers.

## E-09 — /portal/parent linked any account as a child, unconsented (P0)

Submitting an email address inserted a `parent_child_links` row and immediately rendered that
account's name, email, last login, course progress, recent test scores, class schedule and
outstanding fees. No invitation, no acceptance, no verification, and the table had no status column.
It was not exploitable before only because the page had never worked (uuid/bigint mismatch, recorded
in its own header) — repairing the types is what armed it, which is also why there is no existing
access to preserve.

Fixed: links are inserted `pending` and confer nothing; a child renders only when the link is
`accepted` **or** corroborated by `rbac_guardian_links`, the admin-established guardian relationship
this platform already trusts in `student-settings.ts` and `edu-notify.ts`. Re-submitting the form
cannot promote a link. The "no account found" reply is gone — it was an enumeration oracle over the
whole user table — and both outcomes now read identically.

**Follow-up for the owner:** there is no self-service surface for a child to accept. Today the only
route to `accepted` is the admin guardian screen. That is a product decision, not a mechanism.

## E-10 — eleven notification types broadcast to everyone (P1, privacy)

`notify-audience.ts` sent any *unmapped* type to every active non-applicant account — including the
`partner` role its own header says is never an admin. Eleven live types were taking that default:
`activity_alert` / `activity_digest` (the oversight feed: money moved, a permission changed, data
left the building), `paid_application_stuck`, `payment_effect_failed`, `credit_debit_stranded`,
`tool_pass_stranded`, `fee_waiver_request`, `course_fee_waiver_requested`,
`offer_verification_request`, `partner_payout_request`, `application_started`. Named applicants,
rupee amounts and declared financial hardship, to marketing and editors.

Fixed: all eleven mapped to the audience their neighbours already use; the unmapped default is now
super_admin only — never dropped (super_admin receives everything by the first rule) and never
broadcast — with a one-line warning naming the missing type. `notify-audience.test.ts` (76
assertions) scans every `sendPushToAdmins`/`notifyAllAdmins` call site and fails if a new broadcast
type appears with no entry.

## E-11 — the job queue was never drained (P1)

`/api/jobs/run` is the only consumer of `edu_jobs`, and it was in no cron and no workflow, so every
job anything enqueued sat unprocessed. `/api/cron/security-scan` — "the serverless replacement for a
resident continuous monitoring daemon" — was likewise scheduled nowhere, so its detection latency was
infinite. Both were already recorded as open findings in `docs/ops/MONITORING.md`.

Its cron door also only accepted `?key=`, and nothing sends that — Vercel Cron and the existing
GitHub Actions runners both use `Authorization: Bearer`. So a scheduler pointed at it would have been
refused on every run. It now uses the canonical `isCronAuthorized` (constant-time, trims a pasted
newline, fail-closed, accepts all three shapes).

Scheduled: both in `vercel.json` plus the paired `CONFIGURED_CRONS`, and
`.github/workflows/jobs-drain.yml` every 15 minutes for a real drain, reusing the `CRON_SECRET` /
`SITE_ORIGIN` secrets `imap-poll.yml` and `task-reminders.yml` already use.

## E-12 — a blind find-and-replace had corrupted live copy (P0)

A sweep replacing the substring `iversity` with `European MOOC consortium` had rewritten every
ordinary English word containing it, in 11 files. All 31 occurrences were verified to be one of three
shapes with no legitimate use anywhere, so the inverse was exact and was applied in full. Among what
it had broken:

- `r['University Name']` — a **CSV header from the real AISHE India export**. The HEI importer had
  stopped matching the column, so every institution name silently imported empty.
- `value="university"` — a **stored enum** on the HEI tier select. The option no longer matched the
  value in the database, so the field could not round-trip and a save rewrote it to the corrupted
  string.
- A broken external URL, placeholder text, and student-facing prose on `/aquintutor/about`,
  `/aquintutor/index`, `/aquintutor/systems`, `/apply/step-4`, `/apply/step-5`.

## E-13 — a false accreditation claim on the student dashboard (P0)

The same corrupted strip read **"Accredited by — University Grants Commission (India), AACSB, ABET,
European University Association, WASC Senior"**. Five real accreditation bodies, named on a
student-facing page, as though they had accredited this platform. None has. It breaks both standing
rules at once — never claim to be a university or to confer degrees, never name a real organisation
in user-facing copy — and in India that claim is reserved by UGC Act ss.22-24.

Removed outright. Nothing replaces it: a row of logos asserting standing we do not have has no
honest smaller version.
