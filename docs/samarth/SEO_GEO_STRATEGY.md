# SAMARTH SEO and GEO strategy

## Built
- Semantic, server-rendered pages; crawlable sub-navigation; visible breadcrumbs and `BreadcrumbList`.
- Canonical URLs (site layout strips trailing slashes); `noindex` on every private page.
- Sitemap entries for every public SAMARTH page, the fourteen capability pages generated from the catalogue.
- Structured data as one `@graph` per page: `Organization` (SAMARTH, parent EduRankAI, area served worldwide), `OfferCatalog` of services and of packages with `PriceSpecification`, `Service` per capability, `FAQPage` on the consultation and capability pages.
- Fourteen capability pages (Part 15.4), each with problems, scope, approach, deliverables, stated limits, FAQ and related links; original text; tests enforce substance and unique slugs.
- Edge caching of static content pages for anonymous visitors (fast first byte; Core Web Vitals).
- Minimal client script: inline helpers only; the payment provider's script loads only when someone pays.

## GEO principles applied
Clear, consistent entity statements (`SAMARTH` description, parent, reach); factual capability descriptions; stated limits (regulated work, no awarded-project claims); no fabricated case studies, clients or credentials; no promise of inclusion in AI answers.

## Not built yet (Module 11)
- Translated pages and `hreflang`: none exist, so none are declared (declaring alternates that do not exist is an error).
- Search-console and webmaster verification: needs the owner's accounts.
- Publications, research notes and case studies: only real, permitted material; none exists yet.
- Conversion analytics per service page beyond the platform's existing analytics.
